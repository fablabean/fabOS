02

De la llave al programa

Volvemos a la prueba final de «Prepárate» para ver qué pasa por dentro.

En Prepárate ↗ tu prueba.py le pidió un saludo al modelo. Ese programa corto tiene todo lo que hace falta para integrar IA: una llave, un modelo, un pedido y una respuesta.

En palabras simples: llamar a la API es como mandar un mensaje por mensajería con remitente pagado. La llave dice quién paga; el modelo es a quién le escribes; el system es el oficio que le pides que cumpla («eres un clasificador de correos»); los mensajes son la carta; y la respuesta llega con la cuenta: cuántos tokens leyó y cuántos escribió.

LlaveVa en el .env, nunca en el código.
ModeloMás grande, más capaz y más caro; más pequeño, más rápido.
SystemLas instrucciones fijas: el oficio y las reglas.
MensajesLo que cambia en cada llamada: el correo, el texto, la pregunta.
RespuestaTexto (o JSON) que tu programa usa después.
TokensLo que se cobra: lo que entra más lo que sale.

El mismo prueba.py, ahora con un system que le da un oficio y un texto que cambia. Es el esqueleto de casi cualquier integración.

oficio.py · Claude
from dotenv import load_dotenv
import anthropic

load_dotenv()                      # lee ANTHROPIC_API_KEY del .env
cliente = anthropic.Anthropic()

def clasificar(texto):
    mensaje = cliente.messages.create(
        model="claude-haiku-5-5",
        max_tokens=50,
        system="Clasifica el correo en una sola palabra: urgente, informativo o spam.",
        messages=[{"role": "user", "content": texto}],
    )
    print("tokens:", mensaje.usage.input_tokens, "+", mensaje.usage.output_tokens)
    return mensaje.content[0].text

print(clasificar("Asunto: su factura vence hoy y se suspende el servicio"))

from dotenv import load_dotenv
from google import genai
from google.genai import types

load_dotenv()                      # lee GEMINI_API_KEY del .env
cliente = genai.Client()

def clasificar(texto):
    respuesta = cliente.models.generate_content(
        model="gemini-flash-latest",
        config=types.GenerateContentConfig(
            system_instruction="Clasifica el correo en una sola palabra: urgente, informativo o spam."),
        contents=texto,
    )
    print("tokens:", respuesta.usage_metadata.total_token_count)
    return respuesta.text

print(clasificar("Asunto: su factura vence hoy y se suspende el servicio"))

04

Otras cosas que se conectan

La llamada a la IA casi nunca está sola: algo la dispara y su respuesta va a alguna parte.

Pídele JSON, no párrafos

Si la respuesta la va a leer otro programa (una hoja de cálculo, una base de datos), pídele un formato fijo. Así no hay que «interpretar» lo que escribió.

Instrucción para el modelo
Responde solo con JSON válido, sin texto antes ni después, con esta forma:
{"categoria": "urgente | informativo | spam", "motivo": "una frase", "responsable": "nombre o null"}

Mejor aún: los tres proveedores tienen salida estructurada con esquema (en Claude, con herramientas o salidas estructuradasen Gemini, response_schema con response_mime_type="application/json"en OpenAI, text.format con un esquema JSON). El modelo queda obligado a respetar los campos.

Lo que dispara y lo que recibe

Hojas de cálculo

Leer filas de un CSV o de Google Sheets, llenar una columna con la respuesta.

Correo

Revisar la bandeja cada hora, clasificar y responder o reenviar.

Formularios

Cada respuesta nueva de un formulario pasa por la IA antes de llegar a alguien.

Webhooks

Otro sistema avisa «llegó algo» a una dirección tuya, y tu programa actúa.

La llave es dinero: cuídala

En el .env

Siempre. El código la lee de ahí; nunca va escrita en el programa.

Fuera de Git

.env en el .gitignore. Una llave subida a GitHub la encuentran bots en minutos.

Fuera del chat

No la pegues en una conversación ni en una captura. Si se escapa, bórrala y crea otra.

Costos y límites: cada llamada cuesta fracciones de centavo con modelos pequeños, pero un programa en bucle puede hacer miles. Pon un tope de gasto en la consola de tu proveedor. Si ves el error 429, hiciste demasiadas llamadas seguidas: espera un minuto.

Costos y límites: calcula el costo por caso (tokens de entrada + salida × precio) antes de procesar lotes; registra usage en cada llamada; y ante un 429 reintenta con espera creciente. Fija un tope de gasto mensual en la consola.

05

El concepto de agente

Hasta ahora tu programa hacía una llamada y listo. Un agente decide qué hacer, lo hace, mira el resultado y sigue.

  • Modelo: el que piensa y decide el siguiente paso.
  • Herramientas: lo que puede hacer además de escribir: leer un archivo, buscar, consultar una hoja, enviar un correo.
  • Bucle: pensar → actuar → mirar, una y otra vez.
  • Objetivo: cuándo terminó. Sin objetivo claro, no sabe parar.
  • Límites: cuántos pasos, qué puede tocar y qué necesita tu permiso.

En palabras simples: la API sola es preguntarle algo a un experto por teléfono. Un agente es contratar a alguien con acceso a tus herramientas: le das un objetivo («deja listas las respuestas de los correos urgentes»), y él va abriendo, leyendo y escribiendo hasta terminar. Por eso importan tanto los límites: qué puede tocar y qué tiene que preguntarte.

Ya usaste uno: la IA de tu editor (Claude CodeGeminiCodex) es un agente. Lee archivos, ejecuta comandos, mira el resultado y sigue, y te pide permiso antes de lo delicado. Hoy entiendes cómo funciona por dentro.

El bucle, en código

Así se ve en cualquier proveedor: le pasas al modelo la lista de herramientas; si responde pidiendo una, tu programa la ejecuta y le devuelve el resultado; si responde con texto, terminó.

agente.py · el esqueleto
herramientas = {"leer_archivo": leer_archivo, "buscar_en_hoja": buscar_en_hoja}
mensajes = [{"role": "user", "content": objetivo}]

for paso in range(8):                         # límite: nunca un bucle infinito
    respuesta = modelo(mensajes, herramientas=descripciones)
    if not respuesta.pide_herramienta:        # respondió con texto: terminó
        print(respuesta.texto); break
    nombre, args = respuesta.herramienta, respuesta.argumentos
    resultado = herramientas[nombre](**args)  # tu código actúa, no el modelo
    mensajes += [respuesta.como_mensaje, resultado_como_mensaje(resultado)]

El modelo nunca ejecuta nada: solo pide. Quien ejecuta es tu programa, y ahí pones los límites. En la API real se llama tool use o function calling.
