Antes de empezar: la terminal

La vas a usar en casi todos los pasos. Cinco minutos y le pierdes el miedo.

En palabras simples: la terminal es una ventana donde le das órdenes al computador escribiendo, en vez de hacer clic. Se ve como una caja oscura con texto. Abrirla no daña nada, y en esta guía no tienes que memorizar ni inventar nada: vas a copiar y pegar cada orden.

Ábrela así:

Presiona la tecla ⊞ Windows, escribe PowerShell y presiona Enter. Se abre una ventana con una línea que termina en algo como PS C:\Users\tu-nombre>.

Presiona ⌘ + Espacio, escribe Terminal y presiona Enter. La línea termina en algo como tu-nombre@MacBook ~ %.

Presiona Ctrl + Alt + T. La línea termina en algo como tu-nombre@equipo:~$.

Para dar una orden:

  1. En esta guía cada orden está en un recuadro oscuro con un botón Copiar a la derecha. Haz clic en Copiar.
  2. Ve a la terminal y pega: clic derecho dentro de la ventana (o Ctrl + V).⌘ + V.Ctrl + Shift + V.
  3. Presiona Enter y espera. Cuando vuelve a aparecer la línea del principio, la orden terminó.

Pruébalo con esta, que solo le pide a la terminal que diga «hola»:

echo hola

Es normal que muchas órdenes no respondan nada cuando todo salió bien, y que otras muestren mucho texto mientras instalan. Lo que importa es si al final aparece la palabra error.

Si te pide tu contraseña, es la misma con la que entras al computador. Escríbela aunque no veas nada en pantalla (no se muestran las letras, por seguridad) y presiona Enter.

Cuando una orden diga «abre una terminal nueva», cierra la ventana y ábrela otra vez como arriba: así se entera de lo que acabas de instalar.

El editor: VS Code

Es donde vamos a trabajar las tres sesiones.

En palabras simples: VS Code es el programa donde se escribe código, como un Word para programadores. Es gratis, y adentro trae su propia terminal y los asistentes de IA que vamos a usar.

  1. Entra a code.visualstudio.com y haz clic en el botón azul grande de descarga: ya sabe cuál es tu sistema.
  2. Abre el archivo que bajó (queda en Descargas). Acepta el acuerdo y, cuando aparezcan casillas, márcalas todas: sobre todo «Agregar a PATH». Luego Siguiente hasta Instalar.
  3. Abre el archivo que bajó (queda en Descargas) y arrastra Visual Studio Code a la carpeta Aplicaciones. Ábrelo desde ahí; si pregunta si confías en la app, di que sí.
  4. Dentro de VS Code presiona ⌘ ⇧ P, escribe shell command y elige «Install 'code' command in PATH». Esto deja que la terminal lo abra.
  5. Elige el .deb si tienes Ubuntu o Debian (el .rpm si es Fedora), ábrelo con doble clic y pulsa Instalar.
  6. Ábrelo una vez para ver que funciona. Si ya lo tenías, actualízalo: Ayuda → Buscar actualizaciones.

Descárgalo de code.visualstudio.com e instálalo con las opciones que trae. Si ya lo tienes, actualízalo: Ayuda → Buscar actualizaciones.

En Windows, durante la instalación marca «Agregar a PATH» y «Abrir con Code» en el menú contextual. O instálalo desde la terminal:

PowerShell
winget install -e --id Microsoft.VisualStudioCode

En macOS, arrastra la app a Aplicaciones. Después ábrela, presiona ⌘⇧P, escribe «shell command» y elige «Install 'code' command in PATH».

En Linux, descarga el .deb (Ubuntu, Debian) o el .rpm (Fedora) e instálalo con doble clic, o:

Terminal
sudo snap install code --classic

Para comprobarlo, abre una terminal nueva (como en el paso 00) y pega esto. Debe responder con un número, como 1.106.0:Para comprobarlo, abre una terminal nueva y escribe:

Lo de base: Git, Node.js y Python

Los agentes de terminal corren sobre Node.js; el código de la sesión 03 lo escribimos en Python.

En palabras simples: son tres programas que trabajan por debajo y no se abren como una app. Git guarda el historial de tu trabajo. Node.js y Python son los «motores» que hacen correr los programas del bootcamp. Solo hay que instalarlos y comprobar que la terminal los encuentra.

  1. Git: en git-scm.com/download/win descarga «64-bit Git for Windows Setup», ábrelo y dale Next a todo: las opciones que trae están bien.
  2. Node.js: en nodejs.org descarga la versión que dice LTS, ábrela y dale Next a todo.
  3. Python: en python.org/downloads haz clic en el botón amarillo. Al abrirlo, antes de nada marca abajo la casilla «Add python.exe to PATH» y luego Install Now.

La casilla de Python es la que más problemas evita. Si se te pasó, vuelve a abrir el instalador, elige Modify y márcala.

  2. Python: en python.org/downloads haz clic en el botón amarillo y sigue el instalador.

Un agente en la terminal sesión 02

Los agentes leen tu proyecto, ejecutan comandos y hacen tareas enteras por ti.

En palabras simples: un agente es una IA que, además de conversar, puede leer los archivos de tu proyecto y ejecutar órdenes en tu computador, siempre pidiéndote permiso antes. Vive en la terminal. Para el bootcamp basta con Gemini CLI, que es gratis con tu cuenta de Google.

  1. Abre una terminal nueva y pega esto. Tarda uno o dos minutos y muestra bastante texto: es normal.
npm install -g @google/gemini-cli
  1. Cuando termine, escribe gemini y presiona Enter.

  3. Cuando te salude, escríbele «¿en qué carpeta estoy y qué hay aquí?» y presiona Enter. Para salir, escribe /quit.

Instala al menos uno. Si no sabes cuál, el primero: es gratuito con tu cuenta de Google.

Una llave de API sesión 03

Para que tu propio código hable con el modelo.

En palabras simples: una llave de API es una contraseña larga que le permite a tu propio programa usar la IA. Con la de Gemini basta: es gratis para empezar y es la que usamos en la prueba final.

  1. Entra a aistudio.google.com/apikey con tu cuenta de Google. Si te pide aceptar términos, acéptalos.
  2. Haz clic en Create API key. Aparece una clave larga que empieza por AIza….
  3. Cópiala con el botón de copiar y guárdala en un lugar seguro: una nota privada o tu gestor de contraseñas. En el paso siguiente la usamos.

Una llave de API es una contraseña que le da a tu programa acceso al modelo. Con una basta; la de Gemini tiene nivel gratuito y es la que usaremos en la prueba.

Gemini gratis para empezar

En aistudio.google.com/apikey → Create API key. Solo con tu cuenta de Google.

Anthropic (Claude) con saldo

En console.anthropic.com → API Keys. Necesita una recarga pequeña (desde 5 USD).

OpenAI (GPT) con saldo

En platform.openai.com/api-keys. También con una recarga pequeña.

Cuida tu llave como una contraseña. No la pegues en el chat de la clase, no la subas a GitHub y no la mandes por WhatsApp. Si se te escapa, bórrala en la misma página y crea otra: tarda un minuto. En las de pago, pon un límite de gasto mensual.

Guárdala por ahora en un lugar seguro (tu gestor de contraseñas, por ejemplo). En el siguiente paso la ponemos donde va.

La prueba final

Una carpeta de trabajo y un programa de cinco líneas que le habla al modelo. Si esto funciona, estás listo.

En palabras simples: vas a crear una carpeta para el bootcamp y, dentro, un programa muy corto que le pide a la IA un saludo. Copia y pega cada bloque, uno a la vez, y espera a que termine antes del siguiente.

  1. Crea la carpeta del bootcamp y ábrela en VS Code:
PowerShell
mkdir $HOME\bootcamp-agentic
cd $HOME\bootcamp-agentic
code .
Terminal
mkdir -p ~/bootcamp-agentic
cd ~/bootcamp-agentic
code .
  1. En VS Code abre la terminal integrada (Terminal → Nueva terminal) y crea un entorno de Python con sus librerías:
Terminal de VS Code
py -m venv .venv
.venv\Scripts\activate
pip install google-genai python-dotenv openai anthropic
Terminal de VS Code
python3 -m venv .venv
source .venv/bin/activate
pip install google-genai python-dotenv openai anthropic

Al activarlo, la línea de la terminal empieza con (.venv). Así sabes que estás dentro. El «entorno» es una caja aparte para las librerías de este proyecto, para no desordenar el resto del computador. La instalación tarda un minuto.

Para crear un archivo en VS Code: en el panel de la izquierda pasa el mouse sobre el nombre de la carpeta (BOOTCAMP-AGENTIC) y haz clic en el ícono de la hoja con un +. Escribe el nombre exacto, presiona Enter, pega el contenido y guarda con Ctrl + S⌘ + S.

  1. Crea un archivo llamado .env (con el punto al principio) y pega tu llave así, sin comillas ni espacios:
.env
GEMINI_API_KEY=pega-aqui-tu-llave
  1. Y uno llamado .gitignore, para que la llave nunca termine en GitHub:
.gitignore
.env
.venv/
  1. Crea prueba.py con esto:
prueba.py
from dotenv import load_dotenv
from google import genai

load_dotenv()                      # lee la llave del archivo .env
cliente = genai.Client()

respuesta = cliente.models.generate_content(
    model="gemini-flash-latest",
    contents="Saluda al Bootcamp AGENTIC en una frase corta y entusiasta.",
)
print(respuesta.text)
  1. Ejecútalo:
py prueba.py
python3 prueba.py

Si ves una frase de saludo, lo lograste. Tu editor, tu terminal, Python y tu llave de API funcionan juntos.

¿Algo no funcionó? Ayuda ↓
?

Si algo no funcionó

Lo que más suele pasar, y cómo se arregla.

«no se reconoce como un comando» / «command not found»

La terminal se abrió antes de instalar. Ciérrala del todo —también la de VS Code— y abre una nueva. Si sigue igual, reinicia el computador. En Windows, con Python, reinstálalo marcando «Add python.exe to PATH».

En Windows, python abre la Microsoft Store

Usa py en lugar de python, como en esta guía. O desactiva el atajo en Configuración → Aplicaciones → Alias de ejecución de aplicaciones.

.venv\Scripts\activate da error de permisos

Es la política de PowerShell. Ejecuta Set-ExecutionPolicy -Scope CurrentUser RemoteSigned y vuelve a activarlo.

La prueba dice «API key not valid» o «401»

Revisa el .env: el nombre exacto (GEMINI_API_KEY), sin espacios alrededor del igual, sin comillas, y que el archivo se llame .env y no .env.txt. En Windows, activa «Extensiones de nombre de archivo» en el Explorador para verlo.

«429», «quota» o «rate limit»

Se agotó el cupo del momento. Espera un minuto y vuelve a intentar. Con el nivel gratuito de Gemini pasa si se hacen muchas pruebas seguidas.

El computador es de la empresa y no me deja instalar

Pide a tu área de sistemas permisos de instalación para VS Code, Git, Node.js y Python, o usa un computador personal. Las redes corporativas a veces bloquean npm o las APIs: prueba desde otra red antes del bootcamp.

Nada de lo anterior

Anota el mensaje de error exacto —una captura sirve— y tráelo a la primera sesión, o escríbele al equipo del bootcamp antes. Con el mensaje, casi siempre es un minuto.
